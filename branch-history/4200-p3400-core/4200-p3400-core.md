## Rationale

Everything P3400 needs before any individual facet can exist, and nothing
that belongs to one facet alone.  Seven facet commits sit on top of this one
(`4220` through `4280`); each of them adds one property a label can control,
and none of them adds grammar, lookup, or library scaffolding.

Five things meet here.

* **The label grammar.**  `pre<`*label*`>(...)`, and the same on `post` and
  `contract_assert`.  `cp_parser_assertion_control_specifier` parses the
  bracketed expression; `cp_parser_type_id_1` had to learn that the token
  after a template-argument-like `<` may be an expression rather than a
  type, which is where `p3400-label-rshift.C` and
  `p3400-label-trailing-return.C` come from.  The label is stored in a
  contract operand and travels with it through substitution.

* **The `contract_control` keyword and its lookup.**  This is the most
  invasive change in the paper and the one with no precedent in the
  language: names that are visible only inside an assertion-control
  expression.  `RID_CONTRACT_CONTROL` in `c-common`, the reserved word in
  `init_reswords`, `cp_parser_contract_control_using_directive` for
  `using contract_control namespace N;`, a per-scope list of
  contract-control using-directives in `name-lookup`, a contextual flag
  that `search_unqualified` and `search_usings` (qualified lookup) consult,
  and the module streaming for that list so the directives survive a header
  unit or a named module.  The alternative -- threading a parameter through
  the whole lookup pipeline -- was rejected in both this implementation and
  Clang's.  `contract_control (e)` itself is an lvalue denoting a constexpr
  object of `e`'s deduced type: `finish_contract_control_expr` makes it as a
  template parameter object is (one object for each type and value), and a
  dependent operand is kept as a `CONTRACT_CONTROL_EXPR` until
  instantiation.

* **The facet-probing framework.**  This is what every facet commit calls
  into.  `label_facet_accessible_p` decides that an inaccessible member
  means the type does not *participate* in the facet rather than that the
  program is ill-formed -- the library concept is a requires-expression, and
  P3400 is explicit about this, because a label may carry private helpers
  sharing a facet's name.  `call_label_method` and `constant_facet_value`
  invoke a facet and require the answer to be a constant expression, with
  the diagnostic phrased against the facet and the control object rather
  than left to the constant evaluator.  `build_facet_probe_args`,
  `facet_call_viable_p` and `warn_near_miss_facet` implement
  `-Wcontract-invalid-label-facet`: a member that would be the facet if it
  were accessible, if it were `const`, or both, is reported -- relaxing only
  access and constness, so that a member merely sharing a facet's name is
  not.  `data_facet_shape_p` and `warn_near_miss_data_facet` do the same for
  the data-member facets `allowed_semantics` and `group_names`, reporting a
  member of the facet's shape that is inaccessible or not `const`.  The
  near-miss list is the enumeration of the implemented facets and is the
  place a new one has to be registered.

* **`resolve_contract_label`.**  The single entry point that validates a
  label and computes everything derived from it: that the type has an
  accessible nested `assertion_control_object`, the near-miss sweep, both
  trampolines, materialisation of a prvalue label as a `constexpr` variable
  when the runtime needs its address, and the `allowed_semantics`
  intersection.  It is called from `grok_contract` for a label available at
  parse time and again from `tsubst_contract` once a dependent label is
  concrete.

* **The library scaffolding.**  `<contracts>`'s `labels` namespace: the
  eight facet concepts, `empty_label`, `review`, `fixed_message_label`,
  `assertion_group_label` and `""group`, and the whole
  `__combined_label` machinery behind `operator|` -- decomposed base classes
  for the data-member facets and constrained inline methods for the method
  facets, sixteen combinations of which have to compose correctly.  Plus
  `__cpp_lib_contracts_labels` in `version.def` and the `std` module
  exports.

**What a reviewer will not expect to find here -- for now.**
`resolve_contract_label` is the largest single addition on the branch (361
lines) and it contains per-facet code -- the `allowed_semantics` probe loop,
the two trampoline detections -- that by rights belongs in `4230`, `4260`
and `4280`.

The net diff files it as one segment, and a selector claims a whole segment,
so dividing it takes explicit cut points.  `branch-history/splits.md`
declares them, and the function is carried here as three pieces (`:0`, `:1`,
`:2`).  **All three are claimed by this commit**: routing the per-facet
pieces to `4230`, `4260` and `4280` is a matter of moving two selector
entries rather than rewriting the function, and that re-attribution is not
made.  The 473-line `labels` namespace in `<contracts>` is in the same
position and has no cuts declared.

**Dimensions.**  P3400 has one further facet, `dimensions` /
`dimensioned_label`, which is not implemented: it is a pure library
constraint checked by `operator|`, with no compiler involvement, and its
design is being reconsidered.  Sequence number **4290** is reserved for it,
after `4280-p3400-facet-queryable` and before `4600-p4283`, so that adding
it later renumbers nothing.

Upstream's `get_evaluation_semantic`, which decoded a contract's semantic
operand on every call, is deleted here together with its `contracts.h`
declaration: this commit removes the body, and its last callers went in
`2400-p3595` and `3610-constexpr-contract-evaluation`.

`CONTRACT_CONTROL_EXPR` is marked as an expression in `cp_common_init_ts`, so
a dependent one in a template has a `TREE_TYPE` to ask about (GCC-654,
`contract-control-template.C` on a checking build).  Without
`-fcontracts-p3400`, the skip over a label's `<...>` stops at the end of the
declaration when the `>` is missing (GCC-665, `label-recovery-unterminated.C`).

## Compile gap

This commit does not build on its own, and the direction of the break is
worth stating plainly: the *core* has the forward references, not the
facets.

* `resolve_contract_label` calls `build_local_violation_trampoline`
  (`4260-p3400-facet-local-violation-handler`) and `build_query_trampoline`
  (`4280-p3400-facet-queryable`).  Both would need a declaration and a stub
  returning `NULL_TREE`.  They cannot travel with their callers because the
  caller is the indivisible segment described above.

* `grok_contract` and `tsubst_contract`, which are not in this entry, call
  `apply_label_string_facet` and `reresolve_contract_label_facets`
  (`4250-p3400-facet-string-transforms`), and the semantic resolution calls
  `apply_compute_semantic` (`4220`) and `ensure_contract_groups` (`4240`).

* `<contracts>`'s `is_nonthrowing`, `is_checked` and `is_terminating`
  name the `assume` and `noexcept_*` enumerators, which arrive with
  `6000-p3100-core` and `4800-p4298`.

* Outside P3400: the trampoline builders here rely on
  `begin_contract_trampoline` / `finish_contract_trampoline` /
  `abandon_contract_trampoline` / `trampoline_scope` from
  `2600-source-location-machinery`, and the label's runtime surface lands in
  the `__cxa_contract_data_block` chain from `2200-libcontracts`.

The semantic trap is that stubbing those out is *quiet*.  A stubbed
trampoline builder leaves the corresponding map empty, which is
indistinguishable from a label that does not have the facet -- so the
program still compiles, still runs, and still reports violations, just
without ever consulting the label.  That shape recurs in every facet commit
below and is recorded again in each; it is the reason the P3400 tests are
overwhelmingly `dg-do run` tests that assert on an observed effect rather
than compile tests that assert on a diagnostic.

The near-miss warning is the one part of the framework that fails loudly,
and only for the mistakes it was built for: an accessible-but-non-const or
private member whose name matches a facet in the list.  A facet that is
absent because nobody wired it up is not on that list and is not reported.

**Behaviour gap: `-fcontracts-p3400` does not yet imply `-fcontracts`.**  The
`LangEnabledBy` expression that turns the base facility on is a single
boolean naming every per-paper flag at once, so it cannot be divided and
lands in `6900-cross-paper-options`.  Until that commit, `-fcontracts-p3400` sets its
own `flag_contracts_*` variable and nothing else, and this commit's own
tests -- which compile with it and expect contracts to be enabled -- fail.
The code is right; only the switch that arms it is missing.
