## Rationale

Add the second proving strategy for the D4405 (P4405) `prove` and
`diagnose` evaluation semantics: proof shadows.  An evaluation that folding
does not settle is proven when the optimizers can show, in a copy of the
function that is optimized but never emitted, that its predicate cannot be
false where it is evaluated.

`-fcontracts-prove-shadow` (implied by `-fcontracts-p4405`, so by the
umbrella `-fcontracts-p3850`; `-fno-contracts-prove-shadow` turns it off)
selects the strategy, `contract_prove_shadow_strategy` in
`c-family/contracts-prove-shadow.cc`, the second registry entry.  It cannot
answer where the front end describes the evaluation, so it uses the
proving interface's deferral (`4900-p4405`): for a deferrable evaluation in
a function that will be optimized it answers `CPR_DEFERRED`, and its marker
is a region placed where the check would have been -- `if
(.CONTRACT_SHADOW_GUARD ()) { if (!pred) .CONTRACT_UNPROVEN (id); }`, with
three new internal functions.  Its assumption for an earlier evaluation
with `ignore`, `observe`, `noexcept_observe` or `assume` whose predicate
has no side effects is a region ending in `.CONTRACT_ASSUMPTION`;
`enforce`, `noexcept_enforce` and `quick_enforce` need none, their checks
calling a noreturn entry point or trapping.  A caller-side precondition's predicate is rebuilt with the
call's arguments for the parameters when every argument it uses can be
evaluated again (no side effects, temporaries or statements); otherwise the
evaluation is not deferred.  While shadows may be active it also takes over
the diagnostics the front-end strategies decide.

The middle end (`contracts-shadow.cc`) does the proving.  A simple IPA pass
before SSA is built copies each function holding an obligation with
`create_version_clone_with_body` into its shadow: an internal function kept
by `force_output` and never inlined, cloned, merged or split, without debug
information.  Every guard is then folded -- to false in the real function,
whose code is therefore exactly what `ignore` gives (the assembly is the
same, `p4405-shadow-same-code.C`) and whose warnings and analyses never see
a region, and to true in the shadow, where an
assumption's tail becomes `__builtin_unreachable ()` and an obligation's
marker stays, noreturn.  The shadow is optimized with the options a front
end gives the analysis-only functions (`contract_shadow_proof_optimization`,
which `4950-p4405-prove-optimize` sets to the proof optimization level's),
or else with its function's own, whatever the function's `optimize`
attribute, which the shadow does not keep; a `-O0` compilation makes
shadows only when a front end gives them options (`contract_shadow_level_p`),
and otherwise folding is final there.  Warnings
are inhibited while a shadow is the current function.  A
GIMPLE pass where `pass_assumptions` runs then decides each obligation --
unproven if a marker survives (after one more look with the ranger at the
condition guarding it), "always false" if it is reached from the entry
without a condition and was not in a loop, proven otherwise -- and discards
the shadow; under `-flto` a pass after the early optimizations does that at
the compile step instead and removes the shadows before anything is
streamed.  Undefined behaviour makes a path unreachable, exactly as an
assumed predicate does, and is a guaranteed premise.

A proof is sound, or conditional when its shadow holds an assumption that
is not guaranteed (`ignore`, `observe`, `noexcept_observe`), an obligation
whose predicate may have side effects, or an unproven obligation (each
marker being noreturn, what follows assumes it).  Both suppress the
diagnostic; the result is recorded per obligation
(`contract_shadow_obligation_result`) for `-fcontracts-prove-assume`.  A
marker duplicated by unrolling, threading or the constructor clones is one
obligation.  Diagnostics are issued in registration order at the end of the
compilation, both the shadows' and, while shadows may be active, those of
evaluations the front-end strategies decided, so that an error does not stop
the compilation before the shadows are optimized; an obligation nothing
decided (an unused inline function, an unshadowable function, a compilation
stopped by an error) is diagnosed as unproven.  Once inlining is done, what
a shadow alone calls or refers to is kept only as a declaration, so no
function used only by predicates is emitted.

Nor does a shadow change how the real code is compiled when nothing is
assumed.  A shadow, the bodies inlined into it and whatever only they call
or refer to are analysis-only code (`contract_analysis_only_p`), and IPA
decides about the real code as if it did not exist: a call from
analysis-only code to real code (`contract_analysis_only_call_p`) does not
count in the inliner's growth estimates and called-once decisions (such
callers are inlined after the real ones, where they can be), where an
offline copy is found removable for the size accounting, in IPA-CP's
propagation, caller statistics and all-contexts clone, in IPA-SRA's
propagation and caller checks, in frequency and comdat-group propagation,
or in ipa-split's called-once test.  Analysis-only code does not count in
the unit size for the inliner's and IPA-CP's budgets, gets no IPA-CP or
IPA-SRA clone, is not split, and is merged with nothing by identical code
folding; the clones made for the real callers leave its calls with the
original.  Nor may the real code come to refer to a definition that is
there only for analysis-only code (`contract_analysis_only_definition_p`):
a COMDAT virtual function a predicate alone calls is not one a load from
an external vtable folds to in real code, unless `-fdevirtualize` keeps it
for the real code's polymorphic calls anyway
(`can_refer_decl_in_current_unit_p`, `gimple-fold.cc`;
`p4405-shadow-same-code-vtable.C`) -- nor to one only a region removed
from the real code needed, with no shadow at all
(`p4405-shadow-same-code-vtable-ignore.C`).  A shadow is named with its own index rather than a clone number
of its function's name, and gives back the function number it took
(`set_last_funcdef_no`), so that later clones and the `.LFB` labels are
named and numbered as without it.  A shadow's references to variables and
functions still count, a limitation `invoke.texi` documents
(`open-bug-p4405-shadow-references.C`).  Tests:
`p4405-shadow-same-code-*.C`, one per decision, comparing the object code
(the assembly where the function numbers matter) with and without the
shadows and with `ignore`.

An evaluation nested in another (DECISIONS.md E169: a precondition of a
call in its predicate) is an obligation nested in the other's, its marker
placed ahead of the call in the other's region on a side branch that never
joins the path again (`CONTRACT_SHADOW_NESTED_KIND`, whose guard is left
unknown in a shadow): it is decided where the call is evaluated, before
undefined behaviour in the callee can make the path unreachable, and is no
premise for what follows.  One a front-end strategy decided at once is
recorded with its result (`contract_shadow_record_nested`).  A nested
`prove` obligation not proven makes every obligation it is nested in
unproven, and one proven only conditionally makes them conditional, so no
assumption is made of them; it is noted with their diagnostics rather than
reported on its own (`effective_result`).  A nested `diagnose` one not
proven soundly makes them conditional too.  Since a nested obligation's
region never rejoins the path, its failure makes no other proof in its
shadow conditional.  A nested `diagnose` obligation of an assertion's
analysis evaluation and the obligation at the same call in the check that
follows are diagnosed once when their diagnostics are the same
(`contract_shadow_set_report_once`).

A predicate's side effects are judged when its shadow is decided: one
whose only possible side effects are direct calls keeps its proofs sound
when, by then, every function it calls is known to be const or pure,
terminating and not throwing -- which GCC's analyses often find of an
inline function not declared so, such as `std::vector::size`.  The
functions are kept alive for that by a garbage-collection root
(`GTFILES`), as are the functions holding the obligations, which give each
diagnostic its "In function" context at the end of the compilation.  The
rest of the context is the front end's: the strategy asks it for a handle
on the context each evaluation is described in
(`c_contract_diagnostic_context`, a hook beside folding's in
`contracts-prove.h`) and the middle end hands the handle back around the
diagnostic (`contract_shadow_diagnostic_context`).  C keeps none; C++
keeps the template instantiation context (`pt.cc`, its refcount held) and
`input_location`, so a deferred diagnostic prints the same "In
instantiation of" and "required from" lines, under the same
`-ftemplate-backtrace-limit`, as one issued at once
(`p4405-shadow-template-context*.C`).

Under `-fcontracts-prove-assume` (implied by `-fcontracts-p4405`) a sound
proof becomes an assumption in the real function, as if the evaluation
were `assume`.  The front end follows the obligation's region with
`.ASSUME (!.CONTRACT_PROVEN (id) || pred)` (a fourth internal function),
which the gimplifier outlines as it does a non-simple `[[assume]]`, so the
predicate is never evaluated and, while the guard is unknown, nothing
follows from it: the real function carries an inert call through the
early and IPA optimizations.  Every shadow is expanded before anything
else (`compile`), so each obligation is decided before the assumption
functions are optimized; a new pass at the start of the late pipeline,
`contract_proven`, then folds each guard to true for a sound proof and to
false otherwise, and `pass_assumptions` and the ranger do the rest.  It
also removes the real function's call for an obligation not proven
soundly, then updates which variables have their address taken: the call
takes the address of what its predicate reads through a reference (an
outlined check's parameters), and a vacuous call would otherwise keep that
in memory and change the function's code.  Under `-flto` the guards are
folded at the compile step, with the decisions, before anything is
streamed; one that reaches expansion is false.  The region of an
unproven obligation goes only then, after the functions to emit are
fixed, so a function only its predicate calls, if not inlined, is still
emitted out of line, a limitation `invoke.texi` documents (GCC-1001).
Folding's proofs need no assumption: a predicate that folds to true tells
the optimizers nothing.  Nor does a proof after an `assume` evaluation of
the same predicate, which the real code already assumes
(`p4405-prove-assume-after-assume.C`).

A premise is guaranteed only where this translation unit decides it, so
that what is linked can never turn a program without undefined behaviour
into one with it.  The assumption regions come from the function's own
body and are this TU's code.  But code the shadow inlines may hold
evaluations too, and a function another TU may provide (inline, comdat,
weak, interposable, an extern inline or C inline definition) may be linked
from a copy that evaluates the same assertion with `ignore`.  The front
ends note the bodies holding such evaluations (`contract_proof_note_premise`,
`4900-p4405`); the inliner reports each inlining
(`contract_shadow_note_inline`, a hook in `tree-inline.cc`): a function
receiving noted code is noted too, and a shadow records the chain of call
sites through which it inlined a replaceable function's noted code -- or
its code at all, when it is a refinable body (`0420-refinable-body`):
another copy may make even an evaluation that leaves no premise here
differently, an `observe` handler storing to memory where an `ignore` copy
does nothing.  When
the shadow's late optimizations begin, while the call graph edges exist, it
relies on a premise this TU does not decide if a copy of its real function
(its node, its inline and IPA clones) calls one of those sites out of line,
or if the shadow calls out of line code whose IPA summary may rest on a
replaceable function's noted evaluations (or a local clone of a refinable
body, which stays available); its proofs are then conditional.
A callee that is not replaceable is decided here: its out-of-line copy is
this TU's.  `contract_proven` checks each copy of an assumption once more
after the inliner's decisions are applied, and drops it from a copy (one
inlined early into another function) that calls such a site out of line;
and a function that keeps an assumption is marked as a refinable body
(`mark_refinable_body`, `0420-refinable-body`), so that callers that do not
inline a definition another TU may provide use nothing its late
optimizations learn from the assumption -- the front end has usually
marked it already, for the evaluation itself, but not for a caller-side
evaluation deferred to the shadow at the call.  The assumption
functions are expanded right after the shadows, before any real function,
so that their ranges are known where the assumptions are used.  An
assumption function is recognised through its clones too, since IPA
passes may clone it and rewrite the `.ASSUME` call (ipa-sra dropping a
parameter).  Tests:
`p4405-premise-*.C`, including multi-TU run tests where the linker keeps
either copy of an inline function the TUs evaluate differently.

That the real code is unchanged is tested by object-code comparison:
`contracts-same-object-code` (`lib/contracts-objects.exp`, loaded by
`g++-dg.exp`), a `dg-final` action that compiles the test again with a
reference set of options (analysis `ignore`) and with each of several
variants, and compares the objects' content -- disassembly, section
contents, relocations, symbols, COMDAT groups and frame descriptions --
regardless of the order of their sections, which can follow the order in
which comdat functions happen to be finished
(`p4405-prove-assume-outlined-unproven.C`).

Hooks outside the strategy's files: its registry entry; constant
evaluation skipping a region and the guard (`constexpr.cc`); the four
passes in `passes.def`; the reachability of a shadow's callees and
references (`ipa.cc`); warning inhibition and giving back a shadow's
function number (`function.cc`); the analysis-only hooks in
`ipa-inline-analysis.cc`, `ipa-inline.cc`, `ipa-inline-transform.cc`,
`ipa-cp.cc`, `ipa-sra.cc`, `ipa-profile.cc`, `ipa-comdats.cc`,
`ipa-split.cc` and `ipa-icf.cc`, and the comdat checks of
`cgraph_node::verify_node` (`cgraph.cc`) and
`symtab_node::verify_base` (`symtab.cc`): a shadow may call or refer to a
symbol ipa-comdats made local to a group the shadow is not in; expanding
the shadows first and the final diagnostics (`cgraphunit.cc`); the inliner's
report (`tree-inline.cc`); and the garbage-collection root
(`Makefile.in`).  The front ends' side is the
interface's.  Shadows are not used in a coroutine, in a module, while
writing a precompiled header, with `-fanalyzer`, or with profile
instrumentation or feedback.  A call in a predicate the shadow holds is
still not evaluated by the program, so its own caller-side evaluations stay
undiagnosed, with or without the assumption
(`p4405-shadow-predicate-call*.C`).  A caller-side marker of a call of a
specialization whose contracts are not yet substituted holds the predicate
`4900-p4405` substitutes for the query (`p4405-shadow-template-caller.C`).

Override shadows (D4405R0, "Virtual Functions"; the front end's regions are
`4940-p4405-override`'s).  An override pair -- a virtual function and a
function it overrides -- is registered with
`contract_shadow_register_override`, and every region names its kind, the
argument of the guard and of `.CONTRACT_ASSUMPTION`: 0 for an ordinary
region, the pair's number for one of that pair's.  `contract_shadow_clone`
makes one shadow per kind among a function's obligations (an override
shadow is suffixed `contract_override`), folding each guard to whether its
region runs there: an ordinary region in every shadow, an override region
only in its pair's.  In an override shadow an ordinary obligation is a
premise, not an obligation -- the ordinary shadow decides it, and the
ordinary shadows are decided first, so an override proof relying on one
not proven soundly is conditional.  An override obligation never gets the
`-fcontracts-prove-assume` assumption.  Its diagnostic, and that of an
override evaluation decided at once (taken over by the strategy whether or
not it is enabled), names the overridden function, at the overriding
function's definition, and is issued only if that function is compiled:
an inline function whose vtable another translation unit emits is analyzed
there.  After an error, when the clone pass never runs, "compiled" is read
from the symbol table's definitions, so these diagnostics are issued as
ordinary ones are.  The override shadows' own strategy (`4940-p4405-override`) defers
the evaluations made in an override shadow, whose markers and premise
regions are this strategy's (`contract_prove_shadow_assumption`, and the
flag-independent `contract_prove_shadow_may_defer_p`); this one leaves them
alone and makes no premise region of a pair.  Without override shadows, an
override pair's evaluation is an ordinary obligation of the overriding
function, decided by its ordinary shadow but diagnosed as the pair's
(`obligation::named`), and the diagnostics wait for the end while either
strategy is enabled.

An evaluation folding found always false is deferred to the shadow too
(DECISIONS.md E195): it is proven if its marker is removed or ruled out,
and "always false" wherever the marker survives, whatever the shadow's
premises (`obligation::folded_false`).  Tests:
`p4405-premise-unproven*.C` (an unproven evaluation is a premise for
the later ones, whose proofs are conditional and never assumed; none at
-O0) and `p4405-shadow-exception-inlined.C` (a path through an exception
thrown in an inlined member function).

Premise copies, a proving strategy of their own
(`-fcontracts-prove-callee-premises`, `contracts-prove-callee-premises.cc`,
implied by `-fcontracts-p4405`, registered ahead of the shadows; D4405R0
Section 4.5): an `observe`, `noexcept_observe` or `ignore` evaluation is a
premise that makes a later proof conditional, also in a callee the shadow
inlines -- but the callees a shadow inlines are the real functions, whose
regions are gone before anything is inlined.  The strategy's assumption
hook only notes that a non-guaranteed region exists; `contract_shadow_clone`
then makes, from the bodies with their regions, a premise copy of each
function holding one that the direct calls of a function with an ordinary
obligation reach, transitively, and of each function such a call reaches one
through (`make_premise_copies`): it executes the ordinary assumption regions
only -- an obligation's guard carries a second argument to tell them apart
-- holds no obligation, and calls the copies.  A shadow whose function calls
such a function gets a premise shadow, which calls the copies.  The copies
and premise shadows are analysis-only code (`analysis_only_fn_p`), so IPA's
decisions about the real code are unchanged, and are named and numbered as
the shadows are.  The ordinary shadows are decided first, exactly as
without the copies; a premise shadow is optimized further only when its
ordinary shadow left an obligation unproven (`skip_retry`), and an
obligation it proves becomes conditional (`settle_retry`, which recomputes
the merged result from each shadow's decision): never diagnosed, never
assumed, and a sound proof is never changed, so the real code is the same
with and without the copies, under `-fcontracts-prove-assume` too.  An
`ignore` precondition or postcondition has no region (GCC-885), so it is
no premise in a copy either.  Tests: `p4405-shadow-callee-premises*.C`
(a postcondition, an inline callee's `contract_assert`, a function reached
through another, a precondition in the callee's body, under `observe`,
`noexcept_observe`, `ignore`, at -O1, and with the `-fno-` form; the
bindels example; not assumed; -O0; the same object code with and without),
`p4405-premise-semantic-copies.C`; tests that pin what a callee's own code
leaves as a premise pass the `-fno-` form.

A predicate that calls functions is assumed as well, when it has no side
effects of its own and nothing in it is evaluated only once
(`contract_prove_shadow_assumable_p`, for the shadows' and the premise
copies' hooks alike): its direct callees are registered with the region
(`contract_shadow_register_assumption`, the third argument of
`.CONTRACT_ASSUMPTION`), and a shadow holding such a region is conditional
unless each of them is found const or pure, terminating and not throwing
when the shadow is decided -- the test an obligation's callees get
(`side_effects_p`).  D4405R0, "Previous Assertions and Undefined Behavior":
a premise calling such functions keeps its own classification.  Tests:
`p4405-own-pre-call-premise*.C` (an accessor in a function's own
precondition, one with a precondition of its own; sound for an `assume`
precondition calling an inline accessor, conditional and not assumed for an
opaque callee, one with a store, one that may throw; a predicate with a
side effect of its own still not assumed; the real code unchanged; a callee's
`observe` precondition through its premise copy).  An obligation's
callees are judged the same way: one called out of line that is a
replaceable definition holding an unsettled evaluation, directly or through
an exact function, leaves the proof conditional, while an exact definition
is judged by its body (`p4405-shadow-unsettled-callee.C`).

Level copies.  A shadow optimized at other options than its callees cannot
use them: after the early optimizations the inliner does not inline a
function optimized at another level into it (`-fdevirtualize` differs
between `-O1` and `-O2`, `-Og` is never inlined into anything else).  So
`contract_shadow_clone` makes, before it folds anything, a level copy
(suffix `contract_level`) of each function a shadow may reach -- through
the direct calls of a function holding an obligation, transitively -- that
is not at the shadows' options (or has its own `optimize` attribute) or
calls one that has a level copy, if it can be copied and the program runs
its body or one like it (not interposable; a refinable body counts, as for
inlining, and a call of its copy made out of line makes the proof
conditional, `undecided_premise_p`): a version of its body at the shadows'
options, folded as the real function is, whose calls of such functions are
calls of their copies (`make_level_copies`).  Every shadow calls the level
copies; a premise shadow and a premise copy call a premise copy first, else
a level copy.  The copies, premise copies included, get the shadows'
options and lose the function's `optimize` attribute
(`set_proof_options`).  Level copies are analysis-only code like the
premise copies -- local, not forced, named and numbered as the shadows are,
ignored by IPA's decisions about the real code, discarded with the shadows
and removed before streaming -- and none is made where every such function
is at the shadows' options already.  What only the shadows call, the level
copies included, keeps its body through the inliner's first removal after
inlining (`contract_shadow_boundary_hold`, `ipa-inline.cc`), so that the
inliner inlines it into them when it inlines functions into all their
callers, as it would the function itself at the shadows' level; a removal
follows (`p4405-prove-optimize-called-once.C`).  `contract_shadow_level_p` (the
compilation is optimized, or a front end gives the options), rather than
each function's own level, decides whether a function's evaluations are
deferred and whether it is shadowed or copied.  In a `-O0` compilation
with such options three things an optimized one does anyway are done for
the analysis-only code: the bodies of external functions (`extern
template` members, `gnu_inline` functions) are analyzed and kept until the
copies are made (`cgraphunit.cc`, `ipa.cc`), IPA pure-const runs for the
functions at the shadows' options (`ipa-pure-const.cc`, each node decided
by its own options as before), and the options let the shadows inline.
And since `-O0` removes nothing, nothing of a region may be left in the
real function: the C family's genericization makes an `if` holding
nothing but regions a region of its own, executed in every shadow, and
gives the real function the statement without its regions
(`c_contract_hoist_region_guards`, called from `c_genericize` after its
dump), so that the gimplifier lowers it as without the regions; and
`fold_regions` removes the assignments standing in for the guards, the
temporaries only the regions used and the locations of the edges out of
their guards.  Nor do the analysis-only functions change the debug
information: a version made for one leaves its function as it was, not
described as an abstract instance nor marked possibly inlined, and so
does a body inlined into one (`tree-inline.cc`,
`ipa-inline-transform.cc`); and `assign_discriminators` (`tree-cfg.cc`)
numbers the real code's blocks as they are without the regions.  What the
regions leave in the early debug information and in the first CFG
cleanup, which see the functions before the regions are removed, still
shows with `-g`, a limitation `invoke.texi` documents (GCC-998).  The
options are built
(`c_contract_proof_optimization`, `contracts-prove-shadow.cc`) as an
`optimize` attribute giving the level would build them from the command
line's -- what the user gave is kept -- after resetting what the command
line's own level forced on what was not given (`-O0`'s no inlining, the
trapping `__builtin_unreachable`), and keeping the command line's
alignment, which an analysis-only function never uses: GCC keeps the last
function's alignment for the next one that sets none, so the shadows'
would change the program's code.  Every option is restored afterwards,
those that are not per function included.  Since the shadows are expanded
first and the target's RTL machinery is set up with the options of the
first function expanded (the hard frame pointer is allocatable only under
`-fomit-frame-pointer`), it is set up before them, with the command
line's options, as for the first real function without the shadows; a
shadow at proof level 0 in an optimized compilation has `-O0`'s.

## Compile gap

None.  The strategy uses `4900-p4405`'s proving interface, including its
deferral hooks, and `4910-p4405-fold`'s registry; the C front end's
emission points, which place the markers and assumptions in C, arrive with
`5000-p4299`, with the `c-p4405-shadow-*.c` tests, as stage 1's and stage
2's C parts do.  The option-summary line naming the flag is part of the
per-paper synopsis block that `6900-cross-paper-options` adds.
