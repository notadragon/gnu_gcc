# One row per reproducer measurement: id | file | mode | flags
#
# Modes:  syntax   -fsyntax-only
#         compile  -c            (needed when the defect is past the front end
#                                 -- GCC-33's ICE is in codegen and -fsyntax-only
#                                 does not reach it)
#         link     -o a.out      (GCC-21 is a driver/link-model gap)
#         run      -o a.out, then execute; the runtime output is part of the
#                  measurement, because the wrong-code bugs compile clean
#
# Flags are the ones the reproducer's own header comment records, and must
# never include a branch-only option: stock has to be able to run the same
# command, or the comparison means nothing.
#
# Where one bug needs more than one invocation to show itself, it gets one row
# per invocation with a lettered id (GCC-15a is the control, GCC-15b the bug).
#
# GCC-17 is one row per -DCASE, and its counterpart in the companion Clang
# fork (CLANG-8) is split the same way: the bug is that the explicit-object
# half of [expr.prim.this]/3 is unenforced while the static half is enforced,
# and a whole-file measurement averages the two halves into one word.  Measured as a single row it reported only the "#error define CASE"
# from the selector, which is a measurement of nothing.
#
# GCC-27 is split the same way, and became so on 2026-09-20 when the branch
# half-fixed it: the declarator-position parse change made case 1 (two friend
# declarations) diagnose, while case 2 (an ordinary declaration redeclared by
# a namespace-scope friend) stayed silent.  Both still reproduce on stock, so
# the row survives -- but measured as one file the branch column reads `error`
# off case 1 alone and says nothing about the half that is still broken.
#
# GCC-45 is one parse-position defect with three symptoms, and it needs one
# row each because no single invocation can show more than one of them.  45a
# is accepts-invalid and 45c is rejects-valid, so they are opposite directions
# and cancel if measured together.  45b is wrong-code and MUST be `run`: every
# declaration in it compiles clean on stock, so a syntax-mode row would read
# `clean` before and after the fix and could never show either the bug or its
# repair -- a compile-only measurement cannot tell an attached contract from a
# silently discarded one.  That is exactly how the trailing-return drop
# survived unnoticed in the test suite for the life of the branch.
#
# GCC-50 needs its C++26 row as a control.  The defect is that a guard makes
# <contracts> empty below C++26, so the interesting measurement is an absence,
# and an absence is indistinguishable from a reproducer that simply does not
# compile.  50b says the same file is clean one -std= higher, which is what
# makes 50a's error mean the guard.
#
# GCC-49 is why _classify treats "confused by earlier errors, bailing out" as
# an ICE.  Its defect is an assertion failure reachable only after an error has
# been emitted, and on a compiler built without checking -- which our Release
# branch compiler is, and the stock nightly is not -- that spelling is what an
# ICE comes out as.  Classified as a mere `error`, the row read `error` both
# before and after the fix and could never have shown the repair.
#
# A -dH row was tried first and was worthless: -dH aborts on ANY error, so it
# reported an abort whether or not the bug was present.  A row that says the
# same thing about a fixed and an unfixed compiler measures nothing.
