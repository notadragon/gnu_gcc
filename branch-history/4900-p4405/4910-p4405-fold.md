## Rationale

Add the first proving strategy for the D4405 (P4405) `prove` and `diagnose`
evaluation semantics, folding, and the flags that select strategies.  An
evaluation with either semantic is diagnosed unless an enabled strategy
proves its predicate; with no strategy enabled every evaluation is diagnosed
("contract assertion cannot be proven"), as `4900-p4405` leaves it.

`-fcontracts-prove-fold` (implied by `-fcontracts-p4405`, so by the umbrella
`-fcontracts-p3850`; `-fno-contracts-prove-fold` turns it off) proves a
predicate that the front end folds to `true` -- `cp_fully_fold` with
constant evaluation that is not manifestly constant-evaluated in C++,
`c_fully_fold` in C, through the hook `c_contract_fold_predicate` each front
end defines -- whether or not it is a constant expression: `x == x`,
`u >= 0u`, `sizeof (T) >= 4` in an instantiation, a `constexpr` call.  A
predicate that folds to `false` is diagnosed as "contract predicate is
always false" instead (an error for `prove`, a `-Wcontract-unproven` warning
for `diagnose`).  Folding assumes nothing but the language's rules, so its
proofs are always sound.  It works on a copy and never evaluates the
predicate; one whose value is known but whose side effects would have to be
dropped (`touch () || true`) does not fold to a constant and stays unproven.

For a caller-side evaluation of a precondition, the predicate is folded with
the call's arguments substituted for the parameters, so that `divide (n, 0)`
against `pre (d != 0)` is always false and `divide (n, 2)` proven.  Only a
by-value parameter of scalar type whose argument folds to a constant without
side effects (or to the address of a static object) is substituted --
default arguments, enumerators, `nullptr`, the elements of a parameter pack
and the arguments of a member function or constructor call included -- and
the copy is abandoned for a predicate containing a statement or a
front-end-specific tree.  A reference parameter, a parameter of class type,
a non-constant argument and a constructor taking an in-charge parameter
(a class with a virtual base) are left unsubstituted, which is still sound:
the parameter is then an unknown value.  A specialization of a template
whose contracts are not yet substituted at the call is folded with the
predicate `4900-p4405` substitutes for the query, so function templates,
constructor templates (through an inheriting constructor too), members of
class templates, packs and default template arguments fold as any other
function does (`p4405-fold-caller-side-template*.C`).

`-fcontracts-prove-assume` (implied the same way) is accepted; it asks for a
soundly proven evaluation to be treated as an assumption, which for a
predicate proven by folding adds nothing, so with folding as the only
strategy it has no effect.

The strategy is `contract_prove_fold_strategy` in
`c-family/contracts-prove-fold.cc`, the registry's one entry; it records
that it never depends on earlier assertions.

## Compile gap

None.  The strategy uses only `4900-p4405`'s proving interface
(`contracts-prove.h`) and declares its own front-end hook there; both hooks
sit beside the front ends' `c_fully_fold`.  The C front end's use of the
dispatcher, and so of this strategy, arrives with the C front end itself in
`5000-p4299`, with the `c-p4405-fold-*.c` tests.  The option-summary line
naming the two flags is part of the per-paper synopsis lines that
`6900-cross-paper-options` adds as one block.

**Behaviour gap: `p4405-fold-umbrella.C` cannot pass before `6900`.**  It
tests that the umbrella `-fcontracts-p3850` turns folding on, and like
`4900-p4405`'s `p4405-umbrella.C` it relies on the umbrella also enabling
`-fcontracts`, which `6900-cross-paper-options` adds.
