## Rationale

The framework every P3100 check funnels into, and nothing that belongs to a
single check.  Twenty-one routed sanitizer checks and fourteen implicit
contract assertions are built on this commit; each of them is a commit of
its own below.

Five things meet here.

* **The routed-check table.**  `gcc/contracts-routed-checks.def` is the
  single source of the wire id space, and ITS ORDER IS THE ABI: an id is a
  row's index, and the same list, in the same order, is compiled into the
  GCC runtime and into Clang.  Three places in the compiler need the list --
  `routed_checks[]` in `cp/decl2.cc`,
  `routed_ubsan_bits[]` in `cp/cp-gimplify.cc`, and the UBSan half of
  `ROUTED_SANITIZER_BITS` in `opts.cc` -- and two of them fail SILENTLY
  when they disagree with it, giving a check that never routes or an `assume`
  that never suppresses instrumentation, with no diagnostic either way.  All
  three are generated from this file rather than written out.  Its header,
  its four reserved rows (wire slots Clang fills and GCC does not), and the
  `#undef`s stay here; each implemented check's row travels with its check,
  with one exception noted under *What is here that a reviewer will not
  expect* below.

* **The option surface.**  `-fcontracts-p3100` and
  `-fcontracts-allow-assume` in `c.opt`, the `-fcontract-sanitize-semantic=`
  and `-fsanitize-noncontract-callbacks` machinery in `common.opt` and
  `opts.cc` (`parse_sanitizer_semantic_options`, `routed_sanitizer_check_p`,
  `resolved_sanitizer_semantic`, `ROUTED_SANITIZER_BITS`), the
  `flag-types.h` enumerations they store into, and the `invoke.texi` prose
  for all of it.  A check's commit adds a row; it never adds an option.

* **The wire descriptors.**  `cp/decl2.cc` emits the per-sanitizer
  descriptor objects the three runtimes read --
  `__ubsan_contract_semantic` (one byte per routed check, indexed by wire
  id), `__asan_contract_semantic` and `__tsan_contract_semantic` -- from the
  same `.def` list.  `cp/cp-gimplify.cc`'s `cp_genericize` is the other end
  of the same idea: a check resolved to `assume` must not be instrumented at
  all, which is realised per function by `no_sanitize` so that it streams
  through LTO.  That one hunk names ASan, the two ASan pointer-pair checks,
  the whole routed UBSan list and TSan together, so it cannot belong to any
  one of them.

* **The implicit-assertion framework.**  `cp/contracts.cc`'s
  `implicit_ub_info` / `implicit_ub_group_info` registry,
  `cp_resolve_implicit_ub_semantic`, `cp_build_implicit_ub_handler` and
  `build_implicit_op_guard`; the three langhooks
  (`resolve_implicit_ub_semantic`, `build_implicit_ub_handler`,
  `build_implicit_bounds_check`) with their defaults, so a middle-end pass
  can ask the C++ front end for a per-site semantic without linking to it;
  `ubsan.h`'s `enum implicit_ub_reaction` and `enum ubsan_null_op` operand
  protocol, `internal-fn.def`'s widened `IFN_UBSAN_NULL` arity, and
  `sanopt.cc`, which must know from the outset that two `IFN_UBSAN_NULL`
  calls may only be merged when their carried reactions match.

* **The pass driver.**  `pass_ubsan` now runs whenever `-fcontracts-p3100`
  is on, with no sanitizer enabled, and its per-statement loop dispatches to
  the signed-overflow, null/alignment and invalid-value lowerings.  The
  gate and the loop are `ubsan.cc`'s `gate` and `execute`; their hunks name
  several checks each and stay here, while each lowering travels with its
  check.

The tests kept here are the ones about the framework rather than about a
check: the option parser (`p3100-sanitize-semantic-*`), the feature-test
macros, the no-flag behaviour, the group and label plumbing, the
`assume` enumerator's unconditional presence in `<contracts>`, the
`contract_violation::report()` default, and the P4298 `noexcept`
interactions that are not specific to one check.

## Compile gap

None: this is the base of the P3100 band and forward-references nothing.
It depends on nothing, and after it the branch builds with
`-fcontracts-p3100` accepted, `-fcontract-sanitize-semantic=` parsed, the
wire descriptors emitted, `pass_ubsan` running -- and no check routed and no
implicit assertion emitted, because every check is a later commit.

What is here that a reviewer will not expect:

* **Four `.def` rows that name checks whose commits are elsewhere.**
  `RUC_ALIGNMENT`, `RUC_OBJECT_SIZE`, `RUC_NONNULL_ATTRIBUTE` and
  `RUC_RETURNS_NONNULL_ATTRIBUTE` are one hunk in the net diff -- the last
  of them wraps onto a second source line, which is what stops the histogram
  algorithm cutting the run -- so they cannot be split across the four
  commits that own those checks.  They are here for the same reason
  `6900-cross-paper-options` exists: a line that cannot belong to one commit
  belongs to the shared one.  The consequence is that routing for
  those four checks is live from this commit rather than from theirs, and
  each of those commits carries only tests.

* **`cxx_builtin_function` in `cp/decl.cc`.**  `pass_ubsan` now runs for
  every function, and its `initialize_sanitizer_builtins` call can first
  create the sanitizer builtins from inside a function body, where
  `pushdecl` routed the `FUNCTION_DECL` through `set_decl_context_in_fn` and
  ICEd.  A builtin is a namespace-scope entity, so the hook escapes to the
  top level before pushing.  This is a consequence of the pass gate above,
  not of any check, and `p3100-no-sanitizer-builtin-init.C` is its test.

* **The `assume` semantic and `-fcontracts-allow-assume`.**  `assume` is a
  new evaluation semantic in the shared registry, not a property of any
  check.  This commit now carries all of it: the `EnumValue` row in `c.opt`,
  the `case CES_ASSUME:` arm of `emit_check_for_semantic` that makes it emit
  no check exactly like `ignore`, its `invoke.texi` paragraph, and the
  option that gates whether it may be named.  Only the help and synopsis
  lines that spell the semantic list out in one string are elsewhere, in
  `6900-cross-paper-options`.

The semantic trap that runs through all of it: a resolution for an implicit
assertion is per site and per enclosing namespace, and must be done in the
front end or in `pass_ubsan` -- before inlining, while `cfun->decl` is still
the function whose namespace the configuration matches.  Anything resolved
later matches the caller's configuration instead, and the only symptom is a
check that quietly does not fire.

**Behaviour gap: `-fcontracts-p3100` does not yet imply `-fcontracts`.**  The
`LangEnabledBy` expression that turns the base facility on is a single
boolean naming every per-paper flag at once, so it cannot be divided and
lands in `6900-cross-paper-options`.  Until that commit, `-fcontracts-p3100` sets its
own `flag_contracts_*` variable and nothing else, and this commit's own
tests -- which compile with it and expect contracts to be enabled -- fail.
The code is right; only the switch that arms it is missing.
