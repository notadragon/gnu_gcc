## Rationale

Implement D4301, "Context Reports for the Contract-Violation Handler":
`contract_violation::report()`, a new noexcept accessor that lazily renders
a diagnostic string a *producer* -- a sanitizer check, eventually
`6000-p3100-core`'s ASan/UBSan/TSan routing -- attaches to a violation,
distinct from the fixed `comment()`/`message()` text.  On the ABI side this
is a field, `CXA_FIELD_REPORT`, whose payload is a
`__cxa_contract_report_populator` (a function-pointer-plus-context pair);
`report()` calls `populate(ctx)` only when both are present, and guards the
call in a `try`/`catch` since a populator -- unlike the rest of the ABI --
may allocate and could throw across a noexcept boundary, in which case it
returns the fixed string `"Error generating report"` rather than
propagating.  `-fcontracts-p4301` gates a `__cpp_contracts_report` compiler
macro and its own `__cpp_lib_contracts_report`/`contracts_report`
library feature-test pair.

It also carries the three lines of `2200-libcontracts`'
`__handle_contract_violation_default` that consume it -- the
`if (const char* __r = violation.report(); ...)` stanza that prints a report
before the rest of the diagnostic.  Those lines cannot precede `report()`,
so the `libstdc++-v3/src/c++26/contract26.cc#0.1` cut in
`branch-history/splits.md` carves them out of the handler and hands them
here.  This commit is therefore the whole of P4301 and nothing else: one
member function, the three lines that call it, and the flag and macros that
gate them.

Neither the field nor the ABI it lives in is this commit's.
`CXA_FIELD_REPORT` is one enumerator of the ABI's field-id enum, declared in
`libcontracts/contracts-abi.h`, mirrored by hand in `gcc/cp/contracts.h` and
restated for C++ in `libstdc++-v3/include/bits/contracts_abi.h` -- all three
of which land with `2200-libcontracts`, along with the rest of the violation
ABI this accessor reads through: the `_M_chain` reshaping of
`contract_violation`, the templated `__cxa_find_field_ptr<T>` every member
function goes through, `libstdc++-v3/src/c++26/contracts_abi.cc`, and the
convenience-library reorganization that moved the `<contracts>`
implementation out of `src/experimental` into `src/c++26`.  Attaching any of
it here instead would make `2200-libcontracts` and `3600-p3099` each define
a member function of a class shape not declared until three thousand band
numbers later; the ABI lands where it is defined, so no such forward
reference exists.

What is left here is what D4301 actually proposes.  On the library side that
is one member function, `contract_violation::report()` in
`src/c++26/contract26.cc`, and its declaration -- the
`#if defined(__cpp_lib_contracts_report)` block that
`branch-history/splits.md` cuts out of the `contract_violation` member list
so the rest of the list can travel with the ABI rework it belongs to.  On
the compiler side it is the `-fcontracts-p4301` flag and the
`__cpp_contracts_report` macro it predefines, plus the matching
`__cpp_lib_contracts_report` / `contracts_report` library feature-test pair.

## Compile gap

This commit's own new code needs nothing forward-declared.  Everything
`report()` reads through -- `bits/contracts_abi.h`, `__cxa_find_field_ptr`,
`CXA_FIELD_REPORT`, the `_M_chain` member it walks, and the
`__cxa_contract_report_populator` type of the field's payload -- is already
in place, having landed with `2200-libcontracts`.  `report()`'s
early return (`if (!__p || !__p->populate) return nullptr;`) is not a stub
standing in for a producer that arrives later -- it is `report()`'s real,
permanent behaviour for a violation nobody has attached a report to, and
every producer that will ever populate `CXA_FIELD_REPORT` (the P3100
sanitizer routing in `6000-p3100-core`, far later) is purely additive: it
can only make `report()` return something instead of `nullptr`, never break
it.  `-fcontracts-p4301` alone is a fully working, if silent, no-op
producer configuration, not scaffolding awaiting a real implementation.

One coupling to this commit remains, and it runs the other way:
`2200-libcontracts`'s `__handle_contract_violation_default` prints
`violation.report()` before the comment, so the default handler calls a
member neither declared nor defined until here.  It is two lines and it is
recorded in that commit's Compile gap; it is not a gap on this side.

**Behaviour gap: `-fcontracts-p4301` does not yet imply `-fcontracts`.**  The
`LangEnabledBy` expression that turns the base facility on is a single
boolean naming every per-paper flag at once, so it cannot be divided and
lands in `6900-cross-paper-options`.  Until that commit, `-fcontracts-p4301` sets its
own `flag_contracts_*` variable and nothing else, and this commit's own
tests -- which compile with it and expect contracts to be enabled -- fail.
The code is right; only the switch that arms it is missing.
