## Rationale

Implement P3290, "Integrating Existing Assertions" -- approved by EWG, not
yet voted into the working draft, which is why this commit's feature-test
macro is a GCC vendor name rather than a `__cpp_` one.  The paper does two
things and this commit does both.

First, a manual-trigger API: three free functions in `std::contracts` --
`handle_enforced_contract_violation`, `handle_observed_contract_violation`,
and `handle_quick_enforced_contract_violation` -- that let code outside a
compiler-recognized contract assertion construct and report a violation
through the same dispatch a compiler-generated check uses.  Each populates a
small P3290-specific contract descriptor (`__p3290_desc`, an
`assertion_kind::manual` descriptor listing source-location, comment, kind,
semantic and detection-mode fields) via the shared static helper
`__do_handle_violation`, then calls the C ABI's `__cxa_contract_violation`
entry point -- the same one every compiler-generated check calls.
`handle_enforced_contract_violation` aborts on any completion of the handler
(a normal return or an escaping exception, matching `enforce`'s termination
contract); `handle_quick_enforced_contract_violation` never invokes the
handler at all, going straight to `__builtin_trap`.

Second, routing the classic C `assert()` macro through the same mechanism.
`<cassert>` and `<assert.h>` are restructured so that the platform's own
`assert.h` is pulled in first via `#include_next` (so `assert` still tracks
the caller's own `NDEBUG`), and then the new `bits/assert_contract.h` --
shared verbatim between the two headers, which is why it deliberately has no
include guard -- layers the contracts integration on top: under C++26,
`-fcontracts-p3290`, and the caller opting in with
`__STDC_WANT_ASSERT_USES_CONTRACTS__`, it `#undef`s and redefines
`assert(...)` to call the new `__cxa_handle_cassert_violation`, an
`extern "C++"` entry point that reports `assertion_kind::cassert` and always
terminates via `std::abort()` regardless of how the handler exits (normal
return or a caught exception) -- matching classic `assert()` semantics
exactly, rather than the milder `enforce` contract-termination behaviour.
The header comment notes libc++ provides the same symbol, so this is meant
as a shared, cross-vendor integration point rather than a GCC-only hook.

The two new library feature-test macros this commit is responsible for,
`__cpp_lib_contracts_api` and `__cpp_lib_assert_can_use_contracts`, are both
gated on the vendor macro `__gcc_contracts_p3290` rather than a standard
one -- there is no `__cpp_contracts_...` macro for this paper because,
unlike P3097 (adopted, and folded into the base `__cpp_contracts` value) and
P3099 (which gets its own `__cpp_contracts_message`), P3290 has not been
voted into the working draft.  The `assertion_kind::manual` and `::cassert`
enumerators the descriptor above reports through are new entries this
commit adds to the `std::contracts::assertion_kind` enum in `<contracts>`.

## Compile gap

The manual-trigger API and the `assert()` integration both funnel through
the same descriptor mechanism: `__p3290_desc_t` / `__p3290_data_block_t` and
`__do_handle_violation` populate fields identified by the
`CXA_FIELD_*` / `CXA_AK_*` / `CXA_ES_*` / `CXA_DM_*` constants and the
`__cxa_descriptor_table_t` / `__cxa_descriptor_data_t` layout, all declared
in `libstdc++-v3/include/bits/contracts_abi.h`.  Nothing is owed for any of
it: that header, and the whole C++ side of the violation ABI it belongs to,
lands with `2200-libcontracts` at band 2200, together with the
`__cxa_find_field_ptr` / `CXA_FIELD_COMMENT` pattern
`contract_violation::comment()` uses and the `contract26.cc` relocation from
`src/experimental` into `src/c++26`.  Where that header lands matters more
than a Compile gap usually does: the descriptor layout is load-bearing for
every field this commit reports, so a wrong offset or a missing constant
would not fail to compile so much as silently mis-tag every reported
violation.  A stub would not be an honest substitute for it.

**Behaviour gap: `-fcontracts-p3290` does not yet imply `-fcontracts`.**  The
`LangEnabledBy` expression that turns the base facility on is a single
boolean naming every per-paper flag at once, so it cannot be divided and
lands in `6900-cross-paper-options`.  Until that commit, `-fcontracts-p3290` sets its
own `flag_contracts_*` variable and nothing else, and this commit's own
tests -- which compile with it and expect contracts to be enabled -- fail.
The code is right; only the switch that arms it is missing.
