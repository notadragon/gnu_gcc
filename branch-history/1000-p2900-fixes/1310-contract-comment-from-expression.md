## Rationale

The comment of a contract violation is the predicate's source text, which
build_comment reads back from the source file between the predicate's start
and finish columns.  That is wrong for source generated by another tool: a
front end that emits C++ with `#line` directives naming the original file
(EDG's C++-generating back end, paired with g++ by `edg-gxx`) leaves g++
reading the original file at the generated code's columns, so an indented
`contract_assert (x > 0)` reports a fragment of the line such as "ssert".

-fcontract-comment-from-expression skips the source text and uses the
pretty-printed predicate, the form build_comment already falls back to when
the source cannot be read.  It is off by default.
