## Rationale

Implement D4451, "Early Adoption of an Always-Enforced Label", behind
`-fcontracts-p4451`: an assertion-control-specifier `< terminating >` after
`pre`, `post` or `contract_assert` makes the contract assertion a
terminating one, every evaluation of which uses a terminating semantic.
`-fcontracts-p3850` and `-fcontracts-p3400` enable it.

With `-fcontracts-p3400` the specifier is an ordinary P3400 label and
nothing here applies: `cp_parser_terminating_specifier` steps aside and
P3400's parse takes it.  Without it only `< terminating >` is accepted,
and `terminating` is not looked up as an expression.  The contract is
marked (`CONTRACT_TERMINATING_P`, a free language flag on the contract
node, which modules stream with the node's other flags) and its
`CONTRACT_ALLOWED_MASK` is set to the semantics P3400's
`std::contracts::labels::terminating` allows -- enforce, quick_enforce
and prove -- so every configured, dynamically selected or
constant-evaluation semantic is adjusted exactly as for that label, and
P3400 subsumes P4451.  No label object is built, so the violation record
is an unlabelled assertion's.  `mismatched_contracts_p` compares the flag:
two declarations' contracts are the same only if both have the specifier
or neither does.

`check_terminating_specifier` makes the two checks of
[basic.contract.control]: a declaration of
`std::contracts::labels::terminating` must precede the specifier --
ordinary visibility, through qualified lookup of whatever entity that
names -- and unqualified lookup of `terminating` from the specifier must
find nothing or only that declaration.  They run where a P3400 label is
parsed: with the deferred predicate in `cp_parser_late_contract_condition`,
so a member function's class is complete and the function's parameters
are in scope, and at the specifier for a lambda's contract and a
`contract_assert`.

`__cpp_contracts` and `__cpp_lib_contracts` take D4451R0's value, 202611L,
under the option (`__cpp_contracts` the greater of that and P3097's), and
`__gcc_contracts_p4451` is defined for the library.  Without
P3400, `<contracts>` declares `std::contracts::labels::terminating` alone,
of the internal type `std::contracts::__terminating_label_t` and in the
inline namespace `__p4451`, so it is never P3400's label, and no
`contract_control` directive; the `std` module exports it.  The libstdc++
feature-test test expects the raised value, `-fcontracts-p3850` implying
the option.

The tests run each case under `-fcontracts-p4451` alone,
`-fcontracts-p3400` alone and both, and the results agree: the kinds of
assertion (pre, post with and without a result name, `contract_assert`,
members, templates, lambdas, a P3097 virtual function, with P3098
captures, P3099 messages and P4283 requires-clauses) at run time under a
configured ignore, observe, quick_enforce, a P3595 configuration and
dynamic selection; constant evaluation and constant initialization;
redeclarations; the two lookup checks, including a later member, a
parameter, and `<cassert>` alone; `import std;`, `import std.compat;`,
`import <contracts>;`, an implementation unit, and the module cases
that do not make the declaration precede; streaming through a CMI; P4405's
prove; the diagnostics and the feature-test macros.  Further run forms
(a trailing or deduced return type, a class template's members defined
in and out of class, a generic lambda, a deduced postcondition and a
`contract_assert` in a function template), the lookup check in templates
(each ill-formed specifier diagnosed once, whatever the instances), the
diagnostics on lambdas and members, and `import std;` without P3400
providing no labels namespace, or under P4451 alone only `terminating`.
The caller-side sequences of D4451R0's "Caller-Side Evaluations" -- a
precondition checked at the call makes an earlier terminating one checked
there too -- with P3595 configurations, dynamic selection,
`-fcontracts-client-check=pre`, outlined checks and P3097 virtual calls
(`p4451-callerside-*`): a later precondition counts unless its semantic at
the call has the run-time effect of ignore (ignore, prove, diagnose), so
assume, the noexcept semantics and a dynamically selected semantic all
count; and P3097 virtual calls in constant evaluation.

## Compile gap

None of its own.  `-fcontracts-p4451` enabling `-fcontracts`
(`flag_contracts`' `LangEnabledBy` list in `c.opt`) and its row in the
documentation's table of papers arrive with `6900-cross-paper-options`,
which owns those cross-paper lists; until then the option still works
wherever contracts are on, as at C++26.
